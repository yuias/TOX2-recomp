# Movies

## This game

The movies of *Tales of Xillia 2* are Bink 1 files (the header magic is `BIKi`) in
`USRDIR/MOVIE/*.DAT`. The game decodes them on the PPU with its own code; none of the 8 SPU images
embedded in the executable is a Bink decoder. The executable imports neither `cellSail` nor
`cellPamf`.

The runtime does not handle these movies. It has no Bink code and no host-side movie player for
them, and no movie file was opened before the stop of the headless runs (see [Status](status.md)).
Whether the game's own decoder needs more than file access and a working RSX to show its frames has
not been examined.

## Inherited code that this game does not use

The rest of this page describes the movie code that came with the runtime from the project it was derived
from. The game of that project played PAMF movies (MPEG program streams with H.264 video and ATRAC3plus audio) through the
`cellSail` player library. The code is built and tested on synthetic data, but this game never binds
its handlers, so it has never run against this game. Removing it is later work: it touches about 20
files (the handler list in `runtime/src/hle/hle.cpp`, the `census: sail` section, the sail service
and the `media_core` tests), and the host movie player may be reused if Bink is later decoded on the
host.

```
game thread -> cellSail HLE -> MoviePlayer (decode thread) -> PAMF demuxer -> FFmpeg decoders
```

### HLE boundary

`cellSail` is implemented at the import surface (`runtime/src/hle/`):

| File | Contents |
| --- | --- |
| `cell_sail_player.cpp` | Memory allocator, player initialise, boot, open, start and finalize, descriptors and their stream database |
| `cell_sail_adapters.cpp` | Graphics and sound adapters: initialise, finalize, preferred and current format, `GetFrame`, `UpdateAvSync` |
| `sail_service.cpp` | `_libsail-control`, a guest service thread that delivers the notify events and calls the game's allocator callbacks in the order the game waits for |
| `cell_pamf.cpp` | `cellPamfReaderGetNumberOfSpecificStreams`, answered from the descriptor's stream database |

Only stream URIs of the form `x-cell-fs://...` that name a PAMF file are accepted; the path is
resolved through the [virtual file system](virtual-file-system.md). The game owns the frame
buffers: they are allocated through its graphics adapter callbacks, and `GetFrame` copies the due
frame into one of them as tightly packed ARGB (the tests use 1280x720 frames with a pitch of 5120).
The game then draws that frame through the RSX like any other texture, so the renderer needs
nothing movie-specific.

The playback clock is the host's steady clock. It starts when the first video frame and the first
audio block have been decoded, so decoder start-up does not make the first frames late. The end
of a movie is generated by the HLE when the clock reaches the end of the stream. Repeat mode is
stored but not acted on.

### Demuxing and decoding

- `runtime/src/media/pamf.*`: the PAMF header parser and an incremental MPEG-PS demuxer (2048-byte
  packs, PES packets, private stream 1 sub-streams). It splits ATRAC3plus into whole frames and
  labels video data with the timestamps present in the stream. It was written from a format
  description (no third-party demuxer code) and is part of the runtime core.
- `runtime/src/media/movie_player.*`: `MoviePlayer`, a decode thread that reads the file in
  chunks, feeds the demuxer and the decoders, and keeps bounded queues of video frames and audio
  blocks. Video frames are handed out when the clock reaches their timestamp; late frames are
  dropped and counted. Audio that nobody pulls is dropped once the clock has passed it, so it never
  holds up the video.
- `runtime/src/media/ffmpeg_api.*`, `ffmpeg_codecs.*` (library `tox2_media`): the FFmpeg loader and
  the decoders behind the codec interfaces in `movie_decoder.h`. H.264 is decoded with frame
  threads and converted with swscale (the matrix, BT.709 or BT.601, comes from the stream's flag, and the source range from the frame).
  ATRAC3plus is decoded to interleaved big-endian float, the format the game asks for. There is no
  resampling (a stream whose rate differs from the requested one logs a warning); the tests use 48 kHz stereo. The same file also holds the raw-frame
  ATRAC3plus decoder behind `atrac_decoder.h`, which is not part of movie playback (see below).
- `runtime/src/media/at3_file.*` and `atrac_decoder.h` (runtime core): the parser for
  ATRAC3plus RIFF/WAVE files (format, `fact` delay and `smpl` loop, archive scan) and the
  frame-decoder interface that `cellAtrac` uses. Movies do not use them; they are described under
  [Audio](audio.md#cellatrac).

FFmpeg is used as the LGPL DLLs of a pinned build, loaded at run time (no import libraries). For
this game only the `cellAtrac` HLE uses it, once that code runs; the movie decoders are the unused
part. See `THIRD_PARTY_NOTICES.md`. `tools/fetch-ffmpeg.ps1 [-From <zip>] [-Force]` downloads
the build named in `cmake/ffmpeg.cmake`, checks its SHA-256, and extracts it to
`generated/deps/ffmpeg/<asset name>/` with a `.verified-sha256` marker (exit codes: 0 success, 1
failure, 2 usage error). Configuration fails with a hint to run the script while it is missing;
the CMake cache variable `TOX2_FFMPEG_DIR` points at another extraction. The build copies the DLLs,
the FFmpeg licence and the notice next to the executables.

### Failure policy

Media problems are never fatal:

- Without usable FFmpeg DLLs the runtime logs `tox2: sail: codecs unavailable: <reason>` once, and
  each movie plays as black frames without sound for the duration of its stream. The same DLLs
  decode `cellAtrac` sounds, so it also logs `tox2: atrac: no decoder: <reason>` and those sounds
  are silent (see [Audio](audio.md#cellatrac)).
- A file that cannot be opened or parsed is logged (`tox2: sail: <path> cannot be played: ...`);
  the game's calls still complete, and the summary line says `not played: <reason>`.
- Demux and decode errors are counted and the affected data is skipped.

### Audio

The ATRAC3plus audio of a PAMF movie is decoded and offered to the game's sound adapter, and the
game pulls it when its mixer runs:

```
MoviePlayer audio blocks -> cellSailSoundAdapterGetFrame (game's sound thread)
  -> game's mixer writes its cellAudio port -> audio engine downmixes to stereo -> output
```

The game's mixer thread waits for a `cellAudio` notify event, which the runtime's audio engine
sends every 5.333 ms. The game's sound thread, which that notify wakes, calls
`cellSailSoundAdapterGetFrame` for the number of samples it wants (stereo float, 48 kHz), mixes
them with its other sounds, and the mixer writes the result into the port block that the next
period plays. Audio that the game does not pull is still dropped once the playback clock has
passed it. See [Audio](audio.md) for the engine and the options.

### Log lines and census

| Line | When |
| --- | --- |
| `tox2: sail: descriptor <addr> for <path>: N streams, a .. b (90 kHz)` | A descriptor was created; `a .. b` is the presentation interval from the header |
| `tox2: sail: movie start <path> at <t> s, flip <n>` | Playback started |
| `tox2: sail: movie <path>: <w>x<h> <fps> fps, D decoded, N delivered, K dropped, audio S samples (U underruns), played X s of Y s` | The movie ended or was finalized |
| `tox2: sail: movie window <path>: a .. b s (W s), F flips (R/s), Z skipped draws, G GetFrame calls (Q/s)` | Flips and `GetFrame` calls during the movie, for measuring the pacing |
| `tox2: sail: movie <path> details: ...` | Debug level: decode and frame copy time per frame, audio counts |
| `tox2: sail: codecs unavailable: <reason>` | The FFmpeg DLLs could not be loaded |

On stop, `census: sail <n> movies` repeats the summary line of every movie played.

## Tests

- `media_core` (no FFmpeg): PAMF parser and demuxer, the movie player with fake codecs, and the
  cellSail HLE driven through fake guest callbacks, all on synthetic data.
- `media_ffmpeg`: the FFmpeg loader, the H.264 and ATRAC3plus decoders (also the raw-frame one
  behind `cellAtrac`) and the conversions, on synthetic data.

Neither reads game files, and there is no command-line tool that decodes a movie. See
[Tests](tests.md) for when each one is registered.
