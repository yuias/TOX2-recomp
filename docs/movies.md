# Movies

The game plays three intro movies after its warning screen (`if_logo.pam`, `ch_logo.pam` and
`op.pam` under `/dev_bdvd/PS3_GAME/USRDIR/Movie/`) through the `cellSail` player library. The
runtime implements the `cellSail` calls the game makes and plays the files on the host:

```
game thread -> cellSail HLE -> MoviePlayer (decode thread) -> PAMF demuxer -> FFmpeg decoders
```

## HLE boundary

`cellSail` is implemented at the game's import surface (`runtime/src/hle/`):

| File | Contents |
| --- | --- |
| `cell_sail_player.cpp` | Memory allocator, player initialise, boot, open, start and finalize, descriptors and their stream database |
| `cell_sail_adapters.cpp` | Graphics and sound adapters: initialise, finalize, preferred and current format, `GetFrame`, `UpdateAvSync` |
| `sail_service.cpp` | `_libsail-control`, a guest service thread that delivers the notify events and calls the game's allocator callbacks in the order the game waits for |
| `cell_pamf.cpp` | `cellPamfReaderGetNumberOfSpecificStreams`, answered from the descriptor's stream database |

Only stream URIs of the form `x-cell-fs://...` that name a PAMF file are accepted; the path is
resolved through the [virtual file system](virtual-file-system.md). The game owns the frame
buffers: they are allocated through its graphics adapter callbacks, and `GetFrame` copies the due
frame into one of them as tightly packed ARGB (1280x720, pitch 5120). The game then draws that
frame through the RSX like any other texture, so the renderer needs nothing movie-specific.

The playback clock is the host's steady clock. It starts when the first video frame and the first
audio block have been decoded, so decoder start-up does not make the first frames late. The end
of a movie is generated by the HLE when the clock reaches the end of the stream. Repeat mode is
stored but not acted on.

## Demuxing and decoding

- `runtime/src/media/pamf.*`: the PAMF header parser and an incremental MPEG-PS demuxer (2048-byte
  packs, PES packets, private stream 1 sub-streams). It splits ATRAC3plus into whole frames and
  labels video data with the timestamps present in the stream. It was written from a format
  description (no third-party demuxer code) and is part of the runtime core.
- `runtime/src/media/movie_player.*`: `MoviePlayer`, a decode thread that reads the file in
  chunks, feeds the demuxer and the decoders, and keeps bounded queues of video frames and audio
  blocks. Video frames are handed out when the clock reaches their timestamp; late frames are
  dropped and counted. Audio that nobody pulls is dropped once the clock has passed it, so it never
  holds up the video.
- `runtime/src/media/ffmpeg_api.*`, `ffmpeg_codecs.*` (library `dal_media`): the FFmpeg loader and
  the decoders behind the codec interfaces in `movie_decoder.h`. H.264 is decoded with frame
  threads and converted with swscale (the streams signal BT.709, limited range). ATRAC3plus is
  decoded to interleaved big-endian float, the format the game asks for. There is no resampling;
  all three movies are 48 kHz stereo. The same file also holds the raw-frame ATRAC3plus decoder
  behind `atrac_decoder.h`, which is not part of movie playback (see below).
- `runtime/src/media/at3_file.*` and `atrac_decoder.h` (runtime core): the parser for the
  ATRAC3plus RIFF/WAVE files in the game's archives (format, `fact` delay and `smpl` loop, archive
  scan) and the frame-decoder interface that `cellAtrac` uses for the game's music and sound
  effects. Movies do not use them; they are described under [Audio](audio.md#cellatrac).

FFmpeg is used as the LGPL DLLs of a pinned build, loaded at run time (no import libraries); it
decodes the movies and, through the interface above, the `cellAtrac` sounds. See
`THIRD_PARTY_NOTICES.md`. `tools/fetch-ffmpeg.ps1 [-From <zip>] [-Force]` downloads the build
named in `cmake/ffmpeg.cmake`, checks its SHA-256, and extracts it to
`generated/deps/ffmpeg/<asset name>/` with a `.verified-sha256` marker (exit codes: 0 success, 1
failure, 2 usage error). Configuration fails with a hint to run the script while it is missing;
the CMake cache variable `DAL_FFMPEG_DIR` points at another extraction. The build copies the DLLs,
the FFmpeg licence and the notice next to the executables.

## Failure policy

Media problems are never fatal:

- Without usable FFmpeg DLLs the runtime logs `dal: sail: codecs unavailable: <reason>` once, and
  each movie plays as black frames without sound for the duration of its stream. The same DLLs
  decode the game's `cellAtrac` sounds, so it also logs `dal: atrac: no decoder: <reason>` and the
  music and sound effects are silent (see [Audio](audio.md#cellatrac)).
- A file that cannot be opened or parsed is logged (`dal: sail: <path> cannot be played: ...`);
  the game's calls still complete, and the summary line says `not played: <reason>`.
- Demux and decode errors are counted and the affected data is skipped.

## Audio

The ATRAC3plus audio is decoded and offered to the game's sound adapter, and the game pulls it
when its mixer runs:

```
MoviePlayer audio blocks -> cellSailSoundAdapterGetFrame (game's sound thread)
  -> game's mixer writes its cellAudio port -> audio engine downmixes to stereo -> output
```

The game's mixer thread waits for a `cellAudio` notify event, which the runtime's audio engine
sends every 5.333 ms. The game's sound thread, which that notify wakes, calls
`cellSailSoundAdapterGetFrame` for the number of samples it wants (stereo float, 48 kHz), mixes
them with its `cellAtrac` sounds, and the mixer writes the result into the port block that the next
period plays. The runtime plays the result through the audio output
(WASAPI with the window, none with `--no-window`; `--audio-dump FILE` writes it to a WAV file). Audio that
the game does not pull is still dropped once the playback clock has passed it, as before. See
[Audio](audio.md) for the engine, the options and `cellAtrac`, which plays the game's music and
sound effects.

## Log lines and census

| Line | When |
| --- | --- |
| `dal: sail: descriptor <addr> for <path>: N streams, a .. b (90 kHz)` | A descriptor was created; `a .. b` is the presentation interval from the header |
| `dal: sail: movie start <path> at <t> s, flip <n>` | Playback started |
| `dal: sail: movie <path>: 1280x720 29.97 fps, D decoded, N delivered, K dropped, audio S samples (U underruns), played X s of Y s` | The movie ended or was finalized |
| `dal: sail: movie window <path>: a .. b s (W s), F flips (R/s), Z skipped draws, G GetFrame calls (Q/s)` | Flips and `GetFrame` calls during the movie, for measuring the pacing |
| `dal: sail: movie <path> details: ...` | Debug level: decode and frame copy time per frame, audio counts |
| `dal: sail: codecs unavailable: <reason>` | The FFmpeg DLLs could not be loaded |

On stop, `census: sail <n> movies` repeats the summary line of every movie played.

## `dal_moviedump`

`dal_moviedump` decodes a `.pam` file without the game, through the same demuxer and decoders:

```sh
dal_moviedump MOVIE.pam [--frames N] [--hash] [--png-dir DIR [--png-every N]]
              [--threads N] [--bt601 | --bt709] [--verbose]
              [--audio [--audio-frames N] [--wav FILE [--wav-seconds N]] [--no-video]]
              [--expect-frames N] [--expect-yuv INDEX:SHA256]... [--expect-rgb INDEX:SHA256]...
              [--expect-pcm SHA256] [--expect-audio-samples N]
```

It prints the stream table, a summary with the frame count, timing and SHA-256 digests of the
decoded planes and the ARGB output, and `moviedump ok` or `moviedump failed`. `--hash` adds one
line per frame, `--png-dir` writes frames as PNG, `--audio` also decodes the audio (sample counts,
PCM SHA-256 of the big-endian float output, levels) and `--wav` writes it as a 16-bit WAV file. The
`--expect-*` options turn it into a check: it exits with 1 when one fails (2 on a usage error).
It reads movies only; the ATRAC3plus files of the game's archives are handled by `dal_audiotool at3`
(see [`dal_audiotool`](audio.md#dal_audiotool)).

## Tests

- `media_core` (no FFmpeg): PAMF parser and demuxer, the movie player with fake codecs, and the
  cellSail HLE driven through fake guest callbacks.
- `media_ffmpeg`: the FFmpeg loader, the H.264 and ATRAC3plus decoders (also the raw-frame one
  behind `cellAtrac`) and the conversions.
- `movie_decode`: `dal_moviedump` on `ch_logo.pam` with pinned hashes (`cmake/movie_decode.cmake`).
